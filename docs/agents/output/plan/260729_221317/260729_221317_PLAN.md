## 목표
- 공개 API 감사에서 확정한 5개 정리 항목을 서로 독립된 배치로 구현한다.
- 대표 Controller·Info 진입점과 XML 공개 확장 5개의 기능·반환값을 유지한다.
- 신규 공개 API와 신규 Deprecated를 추가하지 않는다.
- 각 배치 직후 대상 테스트, 컴파일, API 차이를 검증하여 회귀 원인을 해당 배치 안에서 확정한다.
- 제거 API의 대체 경로와 대체 API가 없는 항목을 소비자 문서에 기록한다.

## 구현 범위
- 제거: `getSystemNotificationManager()`, Core 공개 `getWindowManager()`, Core 공개 `getInputMethodManager()` (`simple_system_manager/src/main/java/kr/open/library/simple_ui/system_manager/core/extensions/SystemServiceExtensions.kt:33`)
- 내부화: `PowerProfile`, `PowerProfileVO`, `CommonTelephonyCallback`, `TelephonyCallbackManager` (`simple_system_manager/api/simple_system_manager.api:683`, `simple_system_manager/api/simple_system_manager.api:1072`)
- 생성 비활성화: `simple_system_manager.BuildConfig` (`simple_system_manager/build.gradle.kts:108`)
- 문서 및 API 기준선: 관련 README, 마이그레이션 문서, 공개 API 감사, `simple_system_manager.api`
- 범위 제외: `NetworkBase`와 두 공개 데이터 타입의 상속 계약 변경, 다음 메이저 버전 번호·일정 확정, 신규 기능, 다른 모듈 공개 API 정리, 기존 오류·반환 정책 변경

## 하네스 기준
- 금지 패턴: system_manager 기능을 `simple_core`·`simple_xml`에 배치하지 않는다(`simple_system_manager/AGENTS.md:46`).
- 계층 경계: View·Window 의존 구현은 `system_manager.xml.*`, View 독립 구현은 `system_manager.core.*`에 둔다(`simple_system_manager/AGENTS.md:55`).
- 의존 방향: `simple_system_manager`는 `simple_core`에만 의존하며 역방향 의존성을 추가하지 않는다(`simple_system_manager/AGENTS.md:4`).
- 동작 경계: PowerProfile 폴백, Telephony SDK·권한 분기, Network 공개 상속·문자열 폴백, SystemBar 캐시·메인 스레드 정책을 변경하지 않는다.
- 공개 계약: 신규 공개 API와 신규 Deprecated를 추가하지 않고, 승인된 제거 항목 외 API 차이를 허용하지 않는다.
- 작업 안전: 사용자 소유의 기존 변경을 보존하고 관련 없는 파일을 포맷하거나 되돌리지 않는다.

## 실패 처리 정책
- 각 마일스톤은 대상 테스트와 API 검증을 통과해야 다음 마일스톤으로 진행한다.
- 컴파일 실패 시 가시성·import·생성 코드 의존을 먼저 확인하고, 동작 변경으로 우회하지 않는다.
- 대상 테스트 실패 시 해당 마일스톤 변경만 원인 후보로 두고 기존 반환값·상태·예외 규칙과 비교한다.
- `apiDump` 후 예상 외 API 차이가 있으면 기준선을 확정하지 않고 소스 가시성 또는 상속 변경을 수정한다.
- 기존 사용자 변경과 충돌하면 파일을 되돌리거나 덮어쓰지 않고 충돌 범위와 선택지를 보고한다.
- 동일 실패가 반복되거나 범위 확장이 필요하면 작업을 중단하고 사용자 판단을 요청한다.

## 테스트 범위

### Unit
- 기존 `testUnit`: 연결성·Telephony 데이터 모델을 포함한 순수 Kotlin 회귀. `NetworkBaseTest`도 유지하여 공개 기반 클래스의 문자열 처리 계약을 검증한다.

### Robolectric
- `SystemServiceExtensionsTest`: 대표 시스템 서비스와 유지 확장.
- `DisplayInfoRobolectricTest`, `FloatingViewControllerRobolectricTest`, `SoftKeyboardControllerRobolectricTest`: XML 내부 서비스 접근 이후 기능.
- `BatteryPropertyReaderRobolectricTest`: 총 용량 폴백.
- `CommonTelephonyCallbackTest`, `TelephonyCallbackManagerRobolectricTest`, `TelephonyInfoBasicRobolectricTest`, `TelephonyInfoRobolectricTest`: SDK 콜백·위임·해제·정리.
- `NetworkCapabilitiesDataRobolectricTest`, `NetworkLinkPropertiesDataRobolectricTest`: 변경하지 않는 공개 상속과 SDK 직접 조회·레거시 문자열 폴백의 전체 회귀.
- `SystemBarControllerExtensionsRobolectricTest`: BuildConfig 비의존 debug 메인 스레드 가드 위임.

### 빌드·정적 분석·API
- `compileDebugKotlin`, `compileDebugUnitTestKotlin`, `assembleDebug`, `:app:assembleDebug`.
- `ktlintCheck`, `:simple_system_manager:lintDebug`.
- 배치별 `apiDump` + diff 직접 판정 + `apiCheck`, 최종 `apiCheck`.

## 리스크
- 외부 소비자의 직접 참조는 다음 메이저에서 컴파일·바이너리 호환이 깨지므로 마이그레이션 문서 누락이 가장 큰 소비자 리스크다.
- Telephony는 내부화만 수행하고 등록·해제 로직을 함께 정리하지 않아야 SDK별 회귀 범위를 제한할 수 있다.
- Network 공개 상속은 범위 밖이므로 `NetworkBase`와 두 데이터 타입의 선언·상속·문자열 폴백에 변경이 섞이지 않았는지 최종 API diff와 전체 테스트에서 확인한다.
- BuildConfig 비활성화는 생성 타입 참조가 한 건이라도 남으면 컴파일 단계에서 실패한다.
- 작업 트리가 이미 수정된 상태이므로 관련 없는 변경을 포함한 대량 포맷과 되돌리기 명령을 사용하지 않는다.
