## 1. 기술적 타당성
- 다섯 변경은 모두 신규 공개 API 없이 구현할 수 있다. 제거 대상과 유지 대상은 현재 API 기준선에 각각 식별되어 있다(`simple_system_manager/api/simple_system_manager.api:1`, `simple_system_manager/api/simple_system_manager.api:476`, `simple_system_manager/api/simple_system_manager.api:683`, `simple_system_manager/api/simple_system_manager.api:1072`).
- `getSystemNotificationManager()`는 이미 `getNotificationManager()`에 위임하므로 별칭 삭제가 동작 구현을 제거하지 않는다(`simple_system_manager/src/main/java/kr/open/library/simple_ui/system_manager/core/extensions/SystemServiceExtensions.kt:51`, `simple_system_manager/src/main/java/kr/open/library/simple_ui/system_manager/core/extensions/SystemServiceExtensions.kt:72`).

- `PowerProfile` 계열은 내부 `BatteryPropertyReader`가 소유하며 공개 대체 진입점 `BatteryStateInfo.getTotalCapacity()`가 이미 존재한다(`simple_system_manager/src/main/java/kr/open/library/simple_ui/system_manager/core/info/battery/internal/helper/BatteryPropertyReader.kt:36`, `simple_system_manager/src/main/java/kr/open/library/simple_ui/system_manager/core/info/battery/internal/helper/BatteryPropertyReader.kt:50`, `simple_system_manager/src/main/java/kr/open/library/simple_ui/system_manager/core/info/battery/BatteryStateInfo.kt:510`).

## 2. 공개 API 정의

### 2.1 신규 공개 API
- 없음. 대체 목적의 새 공개 함수·클래스·인터페이스를 추가하지 않는다.

### 2.2 제거·변경 공개 API
- `Context.getSystemNotificationManager(): NotificationManager` 제거. `Context.getNotificationManager()`는 유지한다(`simple_system_manager/api/simple_system_manager.api:488`, `simple_system_manager/api/simple_system_manager.api:491`).
- `Context.getWindowManager(): WindowManager`, `Context.getInputMethodManager(): InputMethodManager`를 Core 공개 퍼사드에서 제거한다(`simple_system_manager/api/simple_system_manager.api:484`, `simple_system_manager/api/simple_system_manager.api:498`).
- `PowerProfile`, `PowerProfileVO`와 이들의 공개 멤버를 API 기준선에서 제거하고 모듈 내부 구현으로 전환한다(`simple_system_manager/api/simple_system_manager.api:683`, `simple_system_manager/api/simple_system_manager.api:695`).
- `CommonTelephonyCallback`, 중첩 콜백 타입, `TelephonyCallbackManager`와 이들의 공개 멤버를 API 기준선에서 제거하고 모듈 내부 구현으로 전환한다(`simple_system_manager/api/simple_system_manager.api:1072`, `simple_system_manager/api/simple_system_manager.api:1087`, `simple_system_manager/api/simple_system_manager.api:1092`, `simple_system_manager/api/simple_system_manager.api:1103`, `simple_system_manager/api/simple_system_manager.api:1113`).
- 생성 타입 `kr.open.library.simple_ui.system_manager.BuildConfig`를 API 기준선에서 제거한다(`simple_system_manager/api/simple_system_manager.api:1`).
- 각 독립 배치에서 `:simple_system_manager:apiDump`로 기준선을 갱신하고, 의도한 항목 외 API 차이가 없는지 확인한 뒤 `:simple_system_manager:apiCheck`를 통과시킨다(`simple_system_manager/docs/public_api/PUBLIC_API_AUDIT.md:332`).

### 2.3 유지되는 대체 경로
- 알림 서비스는 `Context.getNotificationManager()`를 사용한다(`simple_system_manager/src/main/java/kr/open/library/simple_ui/system_manager/core/extensions/SystemServiceExtensions.kt:72`).
- 배터리 총 용량은 `BatteryStateInfo.getTotalCapacity()`를 사용한다. `PowerProfile.getAveragePower()`의 개별 전력 지표에는 새 공개 대체 API를 만들지 않는다(`simple_system_manager/src/main/java/kr/open/library/simple_ui/system_manager/core/info/battery/BatteryStateInfo.kt:510`, `simple_system_manager/docs/public_api/PUBLIC_API_AUDIT.md:135`).

- `BuildConfig`가 필요한 소비자는 라이브러리 생성 타입이 아니라 자신의 앱 또는 모듈 빌드 설정을 사용한다(`simple_system_manager/docs/public_api/PUBLIC_API_AUDIT.md:322`).
- `NetworkBase`, `NetworkCapabilitiesData`, `NetworkLinkPropertiesData`의 공개 상속 계약은 대체 없이 현행 유지한다(`simple_system_manager/api/simple_system_manager.api:877`, `simple_system_manager/api/simple_system_manager.api:886`, `simple_system_manager/api/simple_system_manager.api:955`).

## 5. 동작 명세

### 플로우
1. 각 후보를 배치 1부터 5까지 독립적으로 수정한다.
2. 배치별 대상 테스트와 컴파일을 먼저 통과시킨다.
3. `apiDump` 결과에서 해당 배치의 의도된 공개 API 차이만 확인한 뒤 `apiCheck`를 통과시킨다.
4. 실패한 배치는 수정하거나 되돌릴 판단을 마칠 때까지 다음 배치로 넘어가지 않는다. 모듈 검증 원칙도 작은 그룹별 즉시 검증을 요구한다(`simple_system_manager/AGENTS.md:85`).
5. 다섯 배치 완료 후 전체 테스트·정적 분석·빌드·문서 인코딩을 최종 검증한다.

## 7. 영향 범위 / Breaking Change
- 대상 모듈은 `simple_system_manager` 하나이며 `simple_core` 코드는 변경하지 않는다. `simple_system_manager`는 `simple_core`에만 의존한다(`simple_system_manager/AGENTS.md:4`, `simple_system_manager/build.gradle.kts:124`).
- 공개 함수·타입·생성 타입을 제거하므로 소스 및 바이너리 Breaking Change다. 프로젝트 규칙에 따라 Major 증가가 필요한 변경이다(`docs/rules/project/VERSION_RULE.md:19`, `docs/rules/project/VERSION_RULE.md:20`).
- `SystemServiceExtensionsKt` 파일 퍼사드와 유지 함수는 남고 세 멤버만 제거한다(`simple_system_manager/api/simple_system_manager.api:476`, `simple_system_manager/api/simple_system_manager.api:484`, `simple_system_manager/api/simple_system_manager.api:491`, `simple_system_manager/api/simple_system_manager.api:498`).
- PowerProfile·Telephony 내부화는 소비자 직접 생성 경로만 제거하며 `BatteryStateInfo`와 `TelephonyInfo`의 공개 계약은 유지한다(`simple_system_manager/api/simple_system_manager.api:647`, `simple_system_manager/api/simple_system_manager.api:1016`).
- Network 공개 상속은 변경 범위에서 제외했으므로 `NetworkBase`를 상속·타입 검사하는 소비자 계약도 유지된다(`simple_system_manager/api/simple_system_manager.api:877`, `simple_system_manager/api/simple_system_manager.api:886`, `simple_system_manager/api/simple_system_manager.api:955`).
- 라이브러리 `BuildConfig`를 직접 참조한 소비자는 컴파일이 깨진다. 자체 앱·모듈 빌드 설정으로 이동해야 한다(`simple_system_manager/api/simple_system_manager.api:1`, `simple_system_manager/docs/public_api/PUBLIC_API_AUDIT.md:322`).

## 10. 리스크 / 미확인 항목
- 외부 소비자가 제거 API를 직접 참조했다면 컴파일 또는 바이너리 연결이 깨진다. 완화책은 다음 메이저 한정 적용, 통합 마이그레이션 문서, 항목별 대체 경로다(`simple_system_manager/docs/public_api/PUBLIC_API_AUDIT.md:39`, `simple_system_manager/docs/public_api/PUBLIC_API_AUDIT.md:340`).

- 구체적인 다음 메이저 버전 번호와 출시 일정은 PRD에서 범위 제외했으므로 기술 미확인 항목이 아니다.
