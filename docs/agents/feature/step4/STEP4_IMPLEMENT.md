# STEP4. 구현

목적: 마일스톤 루프를 통해 코드를 구현하고 각 마일스톤을 독립 검증한다.

## Tier별 루프 구조

| | Tier A | Tier B |
|---|---|---|
| 루프 기준 | PLAN.md 마일스톤 순서대로 반복 | 단일 구현 사이클 (1회) |
| 하네스 기준 | PRD 금지 패턴·경계 조건·SPEC 판단 기준 | 해당 없음 |
| PRD·SPEC 참조 | 마일스톤마다 확인 | 없음 |

## 진입 조건

- STEP3 하네스를 통과했다
- STEP3 산출물에서 아래 항목이 전달됐다
  - [ ] `빌드 기준선` — 기록됐다
  - [ ] `테스트 기준선` — 기록됐다
  - [ ] `API 스냅샷` — 기록됐거나 "미실행 — 이유"로 명시됐다

**Tier A 추가 진입 조건:**
  - [ ] `PRD 경로` — 파일이 실제로 존재한다
  - [ ] `SPEC 경로` — 파일이 실제로 존재한다
  - [ ] `PLAN 경로` — 파일이 실제로 존재한다
  - [ ] `마일스톤 목록` — 1개 이상 기록됐다

## 행동 원칙

- PLAN.md의 마일스톤 순서를 따른다. 순서 변경 시 사용자에게 확인한다. (Tier A)
- 각 마일스톤 완료 후 반드시 빌드·테스트를 실행하고 사용자에게 보고한 뒤 다음으로 진행한다.
- PRD 금지 패턴을 위반하거나 경계 조건을 이탈하는 구현은 즉시 중단하고 사용자에게 보고한다. (Tier A)
- SPEC 판단 기준에 어긋나는 설계 선택은 사용자에게 확인 후 결정한다. (Tier A)
- 구현 중 마일스톤 범위를 벗어나는 변경이 필요하면 PLAN.md 수정을 사용자에게 먼저 확인한다. (Tier A)

## 마일스톤 루프 체크리스트 (각 마일스톤마다 반복)

Tier B는 이 루프를 1회만 실행한다.

- [ ] L1. 현재 마일스톤 목적을 확인하고 수정 파일을 연다.
  - Tier A: PLAN.md의 해당 마일스톤 `목적`·`수정 파일`·`기준선`을 확인한다.
  - Tier B: STEP1 직접 파일·간접 파일이 수정 대상이다.

- [ ] L2. 코드를 구현한다.
  - Tier A: PRD 금지 패턴을 위반하지 않는지 구현하면서 확인한다.
  - Tier A: PRD 경계 조건을 이탈하는 변경이 발생하면 즉시 중단하고 강제 중단 조건 적용.
  - Tier A: SPEC 판단 기준에 따라 설계 선택을 결정한다. 기준과 어긋나면 사용자에게 확인한다.

- [ ] L3. 빌드를 실행하고 결과를 기록한다.
  - 실행 명령 (PowerShell):
    ```
    powershell -Command "cd 'D:\Android Project\SimpleUI_XML'; .\gradlew.bat :[모듈명]:assembleDebug"
    ```
  - STEP3 빌드 기준선과 비교한다. 기준선이 "통과"였는데 실패이면 → 강제 중단 조건 적용.
  - 기준선이 "기존 실패"였던 항목의 동일 실패는 무시한다.

- [ ] L4. 마일스톤 범위 테스트를 실행하고 결과를 기록한다.
  - 실행 명령 (PowerShell):
    ```
    powershell -Command "cd 'D:\Android Project\SimpleUI_XML'; .\gradlew.bat :[모듈명]:testRobolectric :[모듈명]:testUnit"
    ```
  - STEP3 테스트 기준선과 비교한다. 신규 실패가 있으면 원인을 파악하고 수정한다.
  - 수정 후에도 신규 실패가 해소되지 않으면 → 강제 중단 조건 적용.

- [ ] L5. 하네스 준수를 검증한다.
  - **Tier A**:
    - PRD 금지 패턴: 구현 코드에 금지 패턴이 포함됐는가 — 위반이면 강제 중단 조건 적용.
    - PRD 경계 조건: 구현이 책임 범위 내에 있는가 — 이탈이면 강제 중단 조건 적용.
    - SPEC 판단 기준: 설계 선택이 판단 기준에 따랐는가 — 어긋나면 사용자에게 확인.
  - **Tier B**: "해당 없음 — Tier B"로 기록하고 자동 통과.

- [ ] L6. 마일스톤 완료를 사용자에게 보고하고 다음 마일스톤 진행 확인을 받는다.
  - 보고 형식: 아래 `[마일스톤 N 완료]` 산출물 형식으로 출력한다.
  - 사용자가 다음 진행을 승인하면 다음 마일스톤 L1으로 돌아간다.
  - 사용자가 수정을 요청하면 L2로 복귀한다.
  - 사용자가 중단을 요청하면 강제 중단 조건 적용.

## 하네스

### 공통 하네스

- [ ] 1번 통과 — STEP3 기준선이 확인됐다.
     **CRITICAL** / 미통과 시: STEP3 산출물 재확인. 없으면 STEP3으로 복귀.
- [ ] 2번 통과 — Tier에 맞는 구현 준비가 완료됐다. Tier A이면 PRD·SPEC·PLAN이 열렸다.
     **HIGH** / 미통과 시: 2번 재수행. 파일 열기 실패이면 STEP2로 복귀.

### 마일스톤 루프 하네스 (각 마일스톤마다)

- [ ] L1번 통과 — 마일스톤 목적·수정 파일·기준선이 확인됐다.
     **HIGH** / 미통과 시: L1번 재수행.
- [ ] L2번 통과 — 코드 구현이 완료됐다.
     **CRITICAL** / 미통과 시: L2번 재수행.
- [ ] L3번 통과 — 빌드가 통과됐다. (기준선 "기존 실패" 항목 제외)
     **CRITICAL** / 미통과 시: 원인 파악 후 L2번으로 복귀. 해소 불가이면 강제 중단.
- [ ] L4번 통과 — 신규 테스트 실패가 없다.
     **HIGH** / 미통과 시: 원인 파악 후 L2번으로 복귀. 해소 불가이면 강제 중단.
- [ ] L5번 통과 — 하네스 준수가 확인됐다. Tier B이면 자동 통과.
     **HIGH** / 미통과 시: Tier A PRD 위반·경계 이탈이면 강제 중단. SPEC 기준 불일치이면 사용자 확인.
- [ ] L6번 통과 — 마일스톤 완료 보고가 출력됐고 사용자 확인을 받았다.
     **CRITICAL** / 미통과 시: L6번 재수행.

### 루프 완료 후 하네스

- [ ] 3번 통과 — 전체 마일스톤 완료 산출물이 출력됐다.
     **HIGH** / 미통과 시: 3번 재수행.

미통과 항목이 있으면 실패 규격에 따라 기록 후 강제 중단 조건을 확인한다. 루프 판정 기준은 → [STEP_ROLLBACK.md](../../common/STEP_ROLLBACK.md) 참조

## 산출물

### [마일스톤 N 완료] — 각 마일스톤마다 출력

```text
[feature workflow — 마일스톤 N 완료]
마일스톤    : N. [이름]

구현 파일   : 파일명:라인번호 (수정한 파일 목록)
빌드        : 통과 / 실패(오류 요약)
테스트      : 신규 실패 없음 / 신규 실패 [테스트명 목록]
하네스 준수 : PRD 금지 패턴 준수 / PRD 경계 조건 준수 / SPEC 판단 기준 준수. Tier B이면 "해당 없음"

다음 마일스톤 : N+1. [이름] / 없음(마지막 마일스톤)
```

### [전체 완료] — 모든 마일스톤 완료 후 출력 (STEP5에 전달)

```text
[feature workflow — STEP4 산출물]
단계     : STEP 4 (구현)
진행도   : 완료

완료 마일스톤 : 1. [이름] / 2. [이름] / ... (순서대로)
구현 파일     : 전체 수정된 파일 목록 (파일명:라인번호)

이슈 : [구현/빌드/테스트/하네스/기타] 내용 — 이유. 없으면 "없음"
```

→ 출력 예시는 [STEP4_SAMPLES.md](STEP4_SAMPLES.md) 참조

## 사용자 검증 포인트

각 마일스톤 완료 보고 수령 후 아래 항목을 확인한다.

- [ ] `구현 파일`이 해당 마일스톤 범위 내의 파일만 포함하는가
- [ ] `빌드`가 통과했는가 — 실패이면 원인을 직접 확인한다
- [ ] `테스트`에 신규 실패가 없는가 — 있으면 원인이 납득 가능한지 확인한다
- [ ] Tier A이면 `하네스 준수`가 세 항목 모두 통과인가

## 실패 규격

하네스 미통과 시 아래 형식으로 기록한다.

```text
실패 STEP      : STEP4
실패 마일스톤  : N. [이름] / 공통 체크리스트
실패 항목      : 미통과 하네스 항목명
실패 원인      : 어떤 데이터가 없는지 / 어떤 조건이 충족되지 않는지
복귀 대상      : 해당 체크리스트 항목
전달 데이터    : 완료 마일스톤 목록 / 구현 파일 / 이슈. 미완성 항목은 "미완성"
```

## 강제 중단 조건

복귀 없이 즉시 작업을 멈춘다.

- PRD 금지 패턴 위반이 발견됐다 → 위반 내용을 사용자에게 보고 후 중단 (Tier A)
- PRD 경계 조건 이탈이 발견됐다 → 이탈 내용을 사용자에게 보고 후 중단 (Tier A)
- 빌드 실패가 해소되지 않는다 → 원인과 현재 상태를 사용자에게 보고 후 중단
- 테스트 신규 실패가 해소되지 않는다 → 실패 목록을 사용자에게 보고 후 중단
- 사용자가 마일스톤 진행 중단을 요청했다 → 즉시 중단
- 루프 판정 → [STEP_ROLLBACK.md](../../common/STEP_ROLLBACK.md) 루프 판정 기준 적용
