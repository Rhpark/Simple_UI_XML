# STEP6. 문서화 & 보고

목적: 구현 결과를 REPORT.md로 정리하고, 변경으로 인해 갱신이 필요한 문서를 동기화한다. 후속 워크플로우를 결정해 사용자에게 보고한다.

## 진입 조건

- STEP5 하네스를 통과했다
- STEP5 산출물에서 아래 항목이 전달됐다
  - [ ] `apiCheck` — 기록됐다
  - [ ] `ktlintCheck` — 기록됐다
  - [ ] `전체 테스트` — 기록됐다
  - [ ] `완료 마일스톤 목록` — 기록됐다 (Tier A만)
  - [ ] `구현 파일` — 전체 수정된 파일 목록이 기록됐다
  - [ ] `출력 디렉토리` — `docs/agents/output/feature/YYYYMMDD_HHmmss/` 경로가 확정됐다

## 행동 원칙

- REPORT.md는 구현 사실을 있는 그대로 기록한다. 미완성·이슈가 있으면 숨기지 않고 명시한다.
- 문서 동기화 대상 판단은 변경된 공개 API·KDoc·모듈 문서에 한정한다. 내부 구현 주석은 대상 외다.
- 다음 단계는 Tier 기준으로만 결정한다. 검증 결과에 이슈가 있으면 이슈 항목에 명시하고 다음 단계 결정은 Tier 기준을 따른다.

## 실행 체크리스트

- [ ] 1. 전달된 산출물 항목을 전부 확인한다.

- [ ] 2. 구현 파일 목록을 기준으로 문서 동기화 대상을 확인한다.
  - 아래 항목이 구현 파일과 연관되는지 확인한다.
    - 공개 API KDoc — 변경된 함수·클래스의 KDoc이 구현과 일치하는가
    - 모듈 README 또는 설계 문서 — 사용법·동작 설명이 구현과 일치하는가
    - Tier A이면 PRD·SPEC·PLAN — 구현 결과와 불일치하는 내용이 있는가 (불일치 발견 시 갱신 전 사용자에게 확인한다)
  - 동기화 대상이 없으면 "없음"으로 기록한다.

- [ ] 3. 2번에서 식별된 동기화 대상 문서를 갱신한다. (해당 시)
  - 사용자 승인이 필요한 문서 변경(공개 API KDoc 등)은 변경 내용을 먼저 보고한다.
  - 동기화 대상이 없으면 이 항목을 건너뛴다.

- [ ] 4. 아래 형식에 맞춰 REPORT.md를 작성하고 출력 디렉토리에 저장한다.

  **REPORT.md 형식:**

  ```markdown
  # REPORT — [기능명]

  ## 구현 요약
  [구현한 내용을 2~4문장으로 요약. 외부에서 관찰 가능한 동작 변화 중심으로]

  ## 변경 파일 목록
  [파일명:라인번호 목록]

  ## 마일스톤 완료 목록
  [1. 이름 / 2. 이름 / ... Tier B이면 "해당 없음 — Tier B"]

  ## 검증 결과
  - 빌드: 통과 / 기존 실패 포함
  - 전체 테스트: 통과 N건, 신규 실패 없음 / 통과 N건, 신규 실패 [목록]
  - apiCheck: 통과 / Breaking Change(의도된 변경) / 미실행 — [이유]
  - ktlintCheck: 통과 / 자동 수정 후 통과 / 미실행 — [이유]

  ## 문서 동기화
  [동기화한 문서 목록. 없으면 "없음"]

  ## 이슈
  [미완성·미해소 항목. 없으면 "없음"]

  ## 다음 단계
  [review 권고 / 완료]
  ```

- [ ] 5. 다음 단계를 결정하고 기록한다.
  - **Tier A**: review 권고
  - **Tier B**: 완료

- [ ] 6. 산출물 형식에 맞춰 출력한다.

## 하네스

- [ ] 1번 통과 — 전달된 산출물 항목이 전부 확인됐다.
     **CRITICAL** / 미통과 시: 누락된 산출물 확인 후 해당 STEP으로 복귀.
- [ ] 2번 통과 — 문서 동기화 대상이 식별됐거나 "없음"이 확인됐다.
     **MEDIUM** / 미통과 시: 2번 재수행.
- [ ] 3번 통과 — 동기화 대상이 있으면 갱신됐다. 없으면 자동 통과.
     **MEDIUM** / 미통과 시: 갱신이 필요한 문서를 사용자에게 보고하고 확인 후 재수행.
- [ ] 4번 통과 — REPORT.md가 출력 디렉토리에 생성됐고 필수 섹션이 모두 있다.
     **CRITICAL** / 미통과 시: 4번 재수행.
- [ ] 5번 통과 — 다음 단계가 "review 권고" 또는 "완료" 중 하나로 기록됐다.
     **HIGH** / 미통과 시: 5번 재수행.
- [ ] 6번 통과 — 산출물이 형식에 맞춰 출력됐다.
     **HIGH** / 미통과 시: 6번 재수행.

미통과 항목이 있으면 실패 규격에 따라 기록 후 강제 중단 조건을 확인한다. 루프 판정 기준은 → [STEP_ROLLBACK.md](../../common/STEP_ROLLBACK.md) 참조

## 산출물 (최종 보고)

STEP 완료 시 아래 형식으로 값을 채워 출력한다.

```text
[feature workflow — STEP6 산출물]
단계     : STEP 6 (문서화 & 보고)
진행도   : (n/6) - 마지막으로 완료한 체크리스트 항목명 (진행중 / 완료)

REPORT.md 경로  : docs/agents/output/feature/YYYYMMDD_HHmmss/REPORT.md
변경 파일 목록  : 파일명:라인번호 목록
문서 동기화     : 동기화한 문서 목록. 없으면 "없음"
다음 단계       : review 권고 / 완료

이슈 : [문서/보고/기타] 내용 — 이유. 없으면 "없음"
```

→ 출력 예시는 [STEP6_SAMPLES.md](STEP6_SAMPLES.md) 참조

## 사용자 검증 포인트

AI 산출물 수령 후 아래 항목을 확인한다.

- [ ] REPORT.md `구현 요약`이 실제 구현 내용을 정확히 반영하는가
- [ ] REPORT.md `변경 파일 목록`이 실제 수정한 파일과 일치하는가
- [ ] REPORT.md `이슈`가 "없음"이 아니면 후속 처리 여부를 직접 결정한다
- [ ] `다음 단계`가 review 권고이면 review 워크플로우 실행 여부를 결정한다

## 실패 규격

하네스 미통과 시 아래 형식으로 기록한다.

```text
실패 STEP   : STEP6
실패 항목   : 미통과 하네스 항목명
실패 원인   : 어떤 데이터가 없는지 / 어떤 조건이 충족되지 않는지
복귀 대상   : 해당 체크리스트 항목
전달 데이터 : REPORT.md 경로 / 변경 파일 목록 / 다음 단계 / 이슈. 미완성 항목은 "미완성"
```

## 강제 중단 조건

복귀 없이 즉시 작업을 멈춘다.

- REPORT.md를 생성할 수 없다 → 사용자에게 보고 후 중단
- 루프 판정 → [STEP_ROLLBACK.md](../../common/STEP_ROLLBACK.md) 루프 판정 기준 적용

## 워크플로우 종료

STEP6 완료로 feature 워크플로우가 종료된다.

- **다음 단계 "review 권고"**: review 워크플로우 실행을 사용자에게 안내한다. review 워크플로우는 별도 요청 시 시작한다.
- **다음 단계 "완료"**: 워크플로우가 완전히 종료됐음을 사용자에게 보고한다.
